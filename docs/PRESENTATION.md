## Before final recording or publishing

- **Confirm the actual prototype path:** Which connected screens in Figma are operational? Screen recordings should match those screens, not imagined interactions.
- **Verify NASA imagery:** Show proper credit lines for each sourced image/video and distinguish the team's illustrated game opening from NASA mission photography.
- **Resolve the API line:** The PDF explicitly contains `[NAME THE EXACT NASA SOURCE OR API IMPLEMENTED]` and `[EXPLAIN WHAT INFORMATION IT PROVIDES AND HOW ASTROMIND USES IT]`. Do not read that placeholder literally or substitute an unimplemented API name. If no APIs are implemented, say “We use credited NASA mission information and imagery.”
- **Align team name spellings:** The poster and the supplied script differ for some contributors. See [TEAM.md](TEAM.md).
- **Check technical phrasing:** Distinguish mission design lifetime (e.g. Opportunity's 90-sol target) from actual operating lifetime; do not imply equipment was discarded as waste at launch.
- **Check duration:** The PDF explicitly specifies 0:00–4:00 across its four segments. Speak naturally and trim pauses to stay inside the chosen video requirements.
- **Preview links:** Test Figma permission settings and the GitHub Pages URL from an incognito browser before distribution.

The video editor needs: original Figma start screen, astronaut selection recording, mission-selection recording, one scientific mission fact card, quiz result/feedback recording, authentic NASA images with credits, team poster, and an end card with links.
